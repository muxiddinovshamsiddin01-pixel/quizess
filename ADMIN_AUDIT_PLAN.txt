  ПРОБЛЕМА #1 — ГЛАВНАЯ: Двойная система логина для админа
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

СУТЬ ПРОБЛЕМЫ:
  admin.html имеет СОБСТВЕННЫЙ логин-экран (div#loginScreen), который
  вызывает /api/admin/login и получает отдельный token.

  login.html при is_admin вызывает /api/auth/login и редиректит на /admin,
  но admin.html его не читает — он ждёт своего собственного admin_token
  из sessionStorage.

ИТОГ:
  Если зайти через login.html → попадаешь на /admin → видишь ОПЯТЬ форму
  логина admin.html → нужно вводить пароль ещё раз. ЭТО И ЕСТЬ БАГ.

КАК ДОЛЖНО РАБОТАТЬ:
  1. Пользователь заходит на login.html
  2. Вводит ADMIN_USERNAME + ADMIN_PASSWORD
  3. /api/auth/login возвращает {is_admin: true, username: "shamsiddin", display_name: "Admin"}
  4. login.html делает redirect на /admin
  5. admin.html проверяет sessionStorage/localStorage — видит что юзер уже
     admin — и сразу показывает панель БЕЗ второго логина

FIX (два варианта, выбери один):

  ВАРИАНТ A (проще — убрать дублирование):
    В login.html после получения is_admin:
      - Получить token через отдельный /api/admin/login запрос
      - Сохранить в sessionStorage('admin_token', token)
      - Тогда admin.html уже найдёт токен и покажет панель

  ВАРИАНТ B (чище — единый flow):
    В admin.html убрать div#loginScreen полностью.
    При открытии /admin проверять:
      - Есть ли sq_current_user в localStorage с is_admin === true?
      - Если нет — redirect на /login.html
      - Если есть — получить токен через /api/admin/login автоматически
        (фронт делает POST с сохранёнными кредами... нет, кредов на фронте нет)

  РЕКОМЕНДУЮ ВАРИАНТ A:
    В login.html в функции doLogin(), после if (data.is_admin):

      // Получаем admin token
      const tokenRes = await fetch(API_BASE + '/api/admin/login', {
        method: 'POST',

        body: JSON.stringify({ username, password })
      });
      const tokenData = await tokenRes.json();

    Тогда admin.html найдёт токен сразу и пропустит форму.

Ты сказал "регистрация будет та же" — всё ок, так и работает.

Но! admin никак не отмечен в базе данных sq_users.

Это НОРМАЛЬНО, так и задумано — админ не в базе, его кред в .env.

НО ПРОБЛЕМА: если кто-то зарегистрируется с username = ADMIN_USERNAME
(например "shamsiddin"), то при входе бэкенд сначала проверяет:
  if uname == ADMIN_USERNAME and body.password == ADMIN_PASSWORD:
      return {"is_admin": True, ...}
Если пароль НЕ совпадает — идёт проверка в sq_users.
Т.е. кто-то может занять юзернейм "shamsiddin" и создать обычный аккаунт.
